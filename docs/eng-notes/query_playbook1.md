# Archon — Neo4j Architecture Validation Queries

These queries help validate and analyze the repository dependency graph generated by Archon.

---

# 1. Most Depended-On Files

This query finds files that many other files depend on.

These are often:

* utility modules
* shared abstractions
* framework cores
* architectural hotspots

```cypher
MATCH (f:File)<-[r:DEPENDS_ON]-()

RETURN f.path AS file,
       COUNT(r) AS dependency_count

ORDER BY dependency_count DESC
LIMIT 20
```

### What This Reveals

* central modules
* architecture bottlenecks
* high-impact files
* blast-radius risk areas

---

# 2. Files With Most Dependencies

This query finds files that depend on many other files.

These are often:

* highly coupled modules
* orchestration layers
* complex components

```cypher
MATCH (f:File)-[r:DEPENDS_ON]->()

RETURN f.path AS file,
       COUNT(r) AS dependencies

ORDER BY dependencies DESC
LIMIT 20
```

### What This Reveals

* highly coupled files
* complex architecture regions
* dependency-heavy orchestration layers

---

# 3. Isolated Files

This query finds files that have no dependency relationships.

```cypher
MATCH (f:File)

WHERE NOT (f)-[:DEPENDS_ON]-()

RETURN f.path
LIMIT 50
```

### What This Reveals

* disconnected architecture regions
* standalone scripts
* isolated modules
* possibly unused code

---

# 4. Repository Dependency Density

This query counts total dependency relationships in the repository.

```cypher
MATCH (:File)-[r:DEPENDS_ON]->(:File)

RETURN COUNT(r) AS total_dependencies
```

### What This Reveals

* overall repository coupling
* dependency graph size
* architecture complexity level

---

# Why These Queries Matter

These queries are foundational for:

* architecture analysis
* repository intelligence
* graph analytics
* dependency auditing
* AI-assisted code reasoning

They are also important for debugging graph ingestion pipelines and validating graph correctness.
